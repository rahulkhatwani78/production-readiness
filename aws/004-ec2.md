# AWS EC2: Introduction to Virtual Servers (Beginner's Guide)

When building backend systems, you need a physical computer (a server) to run your application code, host your databases, and handle requests from users. In the past, companies had to buy expensive servers, store them in cold rooms, and hire engineers to maintain them.

**Amazon EC2 (Elastic Compute Cloud)** solves this by allowing you to rent virtual computers in the cloud. You can launch, configure, and scale virtual servers with just a few clicks.

## 1. What is Cloud Computing? (Layman's Terms)

### The Rental vs. Buying Analogy

Imagine you want to start a bakery business.

*   **Traditional On-Premise Approach (Buying):**
    You buy a physical commercial building, install industrial ovens, set up electrical wiring, and buy backup generators.
    *   *Downside:* It costs massive upfront money. If your bakery fails in two months, you lose all that investment. If your bakery becomes an overnight success, you run out of oven space and have to buy a new building, which takes months.
*   **Cloud Computing Approach (Renting):**
    You rent space in a fully equipped shared kitchen down the street. If you need more ovens for a holiday weekend, you pay for extra ovens for just two days. If business is slow, you return the extra ovens and only pay for a single counter.
    *   *Upside:* Low starting cost, flexible scaling, and the building owner handles all building maintenance and power issues.

In software, **Cloud Computing** is the delivery of computing services (servers, storage, databases, networking) over the internet. Instead of buying physical hardware, you rent it from cloud providers like AWS, Microsoft Azure, or Google Cloud.

## 2. What is Amazon EC2?

**EC2** stands for **Elastic Compute Cloud**:
*   **Elastic:** You can easily increase (scale up/out) or decrease (scale down/in) your computing resources dynamically.
*   **Compute:** It provides the processor (CPU) and memory (RAM) power to execute application logic.
*   **Cloud:** The virtual machines live inside Amazon's secure global data centers.

### The Rental Car Analogy

Think of an EC2 instance as renting a car from an agency:
*   If you are going on a solo business trip, you rent a small, fuel-efficient economy car (**`t2.micro`**). It is cheap and does the job.
*   If you are moving heavy furniture, you rent a large, powerful cargo truck (**`c5.xlarge`**).
*   If you need 5 cars for a team event, you rent them for a day and return them.
*   You don't care about oil changes, tire replacement, or car depreciation. The rental agency (AWS) handles all of that.

## 3. Core Concepts of EC2

To launch and run an EC2 instance, you must configure its key building blocks:

```
                  +----------------------------------------------+
                  |              AMAZON EC2 INSTANCE             |
                  +----------------------------------------------+
                    /          |                 \            \
                   v           v                  v            v
           +--------+   +---------------+   +------------+   +-------------+
           |  AMI   |   | Instance Type |   |   Storage  |   |  Security   |
           | (OS)   |   |  (CPU/RAM)    |   | (HDD/SSD)  |   |   Group     |
           +--------+   +---------------+   +------------+   +-------------+
           * Ubuntu     * t2.micro          * EBS Volume     * Firewall    
           * Windows    * c5.large          * Inst. Store    * Open Ports  
```

### A. AMI (Amazon Machine Image)
An **AMI** is a pre-configured template that contains the operating system (OS) and application server software.
*   It is the "blueprint" of your server.
*   When launching an instance, you choose an AMI (e.g., Ubuntu Server 22.04, Amazon Linux 2023, or Windows Server).

### B. Instance Types (Hardware Specs)
AWS groups EC2 instances into families optimized for different workloads. They use a specific naming convention:
*   **Naming Structure:** `[Family][Generation].[Size]` (e.g., `t3.micro`, `c5.xlarge`)
*   **Families:**
    *   **T & M (General Purpose):** Balanced CPU and memory. Great for web servers and development environments.
    *   **C (Compute Optimized):** High CPU power. Used for video encoding, machine learning, or batch processing.
    *   **R (Memory/RAM Optimized):** Massive RAM. Used for in-memory databases (like Redis) or big data processing.
    *   **G (Graphics/GPU Optimized):** Designed for 3D rendering and machine learning training.

### C. Storage Options: EBS vs. Instance Store
*   **Elastic Block Store (EBS):** A network-attached virtual hard drive. EBS is **persistent**—if you stop or restart your EC2 instance, your data remains safe on the EBS volume. (Like a USB flash drive).
*   **Instance Store:** Physical SSD disks directly attached to the physical host computer. These are **temporary (ephemeral)**—if your EC2 instance is stopped or terminates, all data on the Instance Store is permanently lost. (Great for temporary caches).

### D. Security Groups (The Virtual Firewall)
A **Security Group** acts as a virtual firewall that controls the incoming (inbound) and outgoing (outbound) traffic allowed to access your EC2 instance.
*   By default, **all incoming traffic is blocked**.
*   You must create rules to open specific ports:
    *   **Port 22 (SSH):** To log in and configure your Linux server securely.
    *   **Port 80 (HTTP) & Port 443 (HTTPS):** To let public users access your hosted website.

### E. IP Addresses (Public, Private, and Elastic)
*   **Private IP:** Internal address used for communication inside your private cloud network.
*   **Public IP:** Temporary address used to access your server from the internet. **Warning:** If you stop and restart your EC2 instance, the public IP changes.
*   **Elastic IP:** A static, permanent public IP address that never changes, even if you stop and restart your instance.

### F. Key Pairs
EC2 instances do not use passwords for security. Instead, they use cryptography.
*   You create a **Key Pair** consisting of a Public Key (kept by AWS on the server) and a Private Key (downloaded to your computer as a `.pem` file).
*   You use the Private Key file to log in via SSH. **Keep this file secure; anyone with access to it can control your server!**

## 4. Hands-On Command Reference (AWS CLI)

You can manage your EC2 instances using the AWS Command Line Interface (CLI).

### 1. Launch a new EC2 Instance
```bash
aws ec2 run-instances \
    --image-id ami-0c7217cdde317cfec \
    --count 1 \
    --instance-type t2.micro \
    --key-name my-ssh-key \
    --security-group-ids sg-12345678
```
*(This starts a single `t2.micro` instance using a specific Ubuntu AMI, your SSH key, and security group)*

### 2. View running Instances
```bash
aws ec2 describe-instances --filters "Name=instance-state-name,Values=running"
```

### 3. Stop an Instance (Saves money, CPU is paused, EBS storage charges still apply)
```bash
aws ec2 stop-instances --instance-ids i-0abcdef1234567890
```

### 4. Start a Stopped Instance
```bash
aws ec2 start-instances --instance-ids i-0abcdef1234567890
```

### 5. Terminate an Instance (Permanently deletes the server and cleans up resources)
```bash
aws ec2 terminate-instances --instance-ids i-0abcdef1234567890
```

## 5. How to Connect to your EC2 Instance (SSH)

Once your instance is running, you can connect to it securely using a Terminal.

### Step 1: Set Private Key Permissions (Mac/Linux)
Open your terminal, navigate to the folder containing your downloaded `.pem` key, and run:
```bash
chmod 400 my-ssh-key.pem
```
*(This ensures your key is private and not readable by other users on your local computer. SSH will block connections if permissions are too open).*

### Step 2: Connect via SSH
Run the connection command using the default username for your AMI (e.g., `ubuntu` for Ubuntu, `ec2-user` for Amazon Linux):
```bash
ssh -i "my-ssh-key.pem" ubuntu@ec2-54-210-44-12.compute-1.amazonaws.com
```
*(Replace the endpoint with your instance's Public IP or Public DNS address).*

## 6. EC2 Production Checklist

- [ ] Choose the correct **AMI** based on your team's familiarity (Ubuntu vs. Amazon Linux).
- [ ] Select an **Instance Type** that matches your workload; start with burstable general purpose (`t3.medium`) and upgrade as needed.
- [ ] Ensure your root **EBS Volume** has "Delete on Termination" enabled so you don't pay for leftover disks when deleting servers.
- [ ] Restrict **Security Group Inbound Port 22 (SSH)** to your specific IP address instead of opening it to the entire internet (`0.0.0.0/0`).
- [ ] Set up an **Elastic IP** if you require a permanent static IP address for DNS records.
- [ ] Schedule automatic backups using AWS Backup or EBS Snapshots.
- [ ] Attach an **IAM Instance Profile** (Role) to the EC2 instance to let it access services like S3 or DynamoDB securely without storing access keys in your code.
