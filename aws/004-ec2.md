# AWS EC2: Introduction to Virtual Servers (Beginner's Guide)

When building backend systems, you need a physical computer (a server) to run your application code, host your databases, and handle requests from users.

**Amazon EC2 (Elastic Compute Cloud)** allows you to rent virtual computers in the cloud. You can launch, configure, and scale virtual servers with just a few clicks.

## 1. What is Cloud Computing? (Layman's Terms)

### The Rental vs. Buying Analogy

Imagine you want to start a bakery business.

*   **Traditional On-Premise Approach (Buying):** You buy a physical commercial building, install industrial ovens, set up electrical wiring, and buy backup generators.
    *   *Downside:* It costs massive upfront money. If your bakery fails in two months, you lose all that investment. If your bakery becomes an overnight success, you run out of oven space and have to buy a new building, which takes months.
*   **Cloud Computing Approach (Renting):** You rent space in a fully equipped shared kitchen down the street. If you need more ovens for a holiday weekend, you pay for extra ovens for just two days. If business is slow, you return the extra ovens and only pay for a single counter.
    *   *Upside:* Low starting cost, flexible scaling, and the building owner handles all building maintenance and power issues.

In software, **Cloud Computing** is the delivery of computing services (servers, storage, databases, networking) over the internet. Instead of buying physical hardware, you rent it from cloud providers like AWS, Azure, or Google Cloud.

## 2. What is Amazon EC2?

**EC2** stands for **Elastic Compute Cloud**:
*   **Elastic:** You can easily increase (scale up/out) or decrease (scale down/in) your computing resources dynamically.
*   **Compute:** It provides the processor (CPU) and memory (RAM) power to execute application logic.
*   **Cloud:** The virtual machines live inside Amazon's secure global data centers.

### The Rental Car Analogy

Think of an EC2 instance as renting a car from an agency:
*   If you are going on a solo business trip, you rent a small, fuel-efficient economy car (**`t3.micro`**). It is cheap and does the job.
*   If you are moving heavy furniture, you rent a large, powerful cargo truck (**`c5.xlarge`**).
*   If you need 5 cars for a team event, you rent them for a day and return them.
*   You don't care about oil changes, tire replacement, or car depreciation. The rental agency (AWS) handles all of that.

## 3. Core Concepts of EC2

To launch and run an EC2 instance, you must configure its key building blocks:

```
                  +----------------------------------------------+
                  |              AMAZON EC2 INSTANCE             |
                  +----------------------------------------------+
                    /          |                 \            \
                   v           v                  v            v
           +--------+   +---------------+   +------------+   +-------------+
           |  AMI   |   | Instance Type |   |   Storage  |   |  Security   |
           | (OS)   |   |  (CPU/RAM)    |   | (HDD/SSD)  |   |   Group     |
           +--------+   +---------------+   +------------+   +-------------+
           * Ubuntu     * t2.micro          * EBS Volume     * Firewall    
           * Windows    * c5.large          * Inst. Store    * Open Ports  
```

### A. AMI (Amazon Machine Image)
An **AMI** is a pre-configured template that contains the operating system (OS) and application server software. It is the "blueprint" of your server. (e.g., Ubuntu Server 22.04 LTS, Amazon Linux 2023).

### B. Instance Types (Hardware Specs)
AWS groups EC2 instances into families optimized for different workloads. 
*   **Naming Structure:** `[Family][Generation].[Size]` (e.g., `t3.micro`, `c5.xlarge`)
*   **Families:**
    *   **T & M (General Purpose):** Balanced CPU and memory. Great for web servers and development environments.
    *   **C (Compute Optimized):** High CPU power. Used for video encoding, machine learning inference, or batch processing.
    *   **R (Memory/RAM Optimized):** Massive RAM. Used for in-memory databases (like Redis) or big data processing.
    *   **G (Graphics/GPU Optimized):** Designed for 3D rendering and machine learning training.

### C. Security Groups (The Virtual Firewall)
A **Security Group** acts as a virtual firewall that controls the incoming (inbound) and outgoing (outbound) traffic allowed to access your EC2 instance.
*   By default, **all incoming traffic is blocked**. You must explicitly open ports:
    *   **Port 22 (SSH):** To log in and configure your Linux server.
    *   **Port 80 (HTTP) & Port 443 (HTTPS):** To let users access your hosted web applications.

## 4. EC2 Pricing Models

Selecting the correct pricing model can reduce your AWS bill by up to 70%:

| Pricing Model | Description | Cost Savings | Best For |
| :--- | :--- | :--- | :--- |
| **On-Demand** | Pay by the second for compute active. No commitment. | 0% | Short-term, unpredictable workloads. |
| **Savings Plans** | Commit to a consistent amount of compute ($10/hr) for 1-3 years. | Up to 72% | Long-term stable workloads with flexible resources. |
| **Reserved Instances** | Commit to a specific instance type/size for 1-3 years. | Up to 72% | Databases or servers that will never change configuration. |
| **Spot Instances** | Bid on spare AWS compute capacity. AWS can terminate with 2m notice. | Up to 90% | Stateless, fault-tolerant workloads, batch processing, development. |

## 5. Instance Metadata Service (IMDSv1 vs. IMDSv2)

EC2 instances can query information about themselves (such as IP address, IAM Role details, instance type) by calling an internal API at a special non-routable IP address: `http://169.254.169.254/latest/meta-data/`.

*   **IMDSv1 (Legacy):** Uses simple HTTP GET requests. High risk if an application is vulnerable to SSRF (Server-Side Request Forgery) attacks.
*   **IMDSv2 (Secure):** Requires a session-oriented token-based system. Access token must be requested via a PUT request first:
    ```bash
    TOKEN=$(curl -X PUT "http://169.254.169.254/latest/api/token" -H "X-aws-ec2-metadata-token-ttl-seconds: 21600")
    curl -H "X-aws-ec2-metadata-token: $TOKEN" http://169.254.169.254/latest/meta-data/local-ipv4
    ```

## 6. Step-by-Step Guide: Launching an EC2 Instance in the Console

### Step 1: Launch Wizard
1. Open the **AWS Console** and search for **EC2**.
2. Click **Launch instance** (orange button).
3. Set the following settings:
   * **Name:** `production-api-server`
   * **Application and OS Images (AMI):** Select **Ubuntu** (Ubuntu Server 22.04 LTS).
   * **Instance type:** Select `t2.micro` (or `t3.micro` if available in free-tier).
   * **Key pair:** Click *Create new key pair*. Name it `my-ssh-key`. Choose **RSA** and **.pem** format (use `.ppk` if using PuTTY on Windows). Click *Create key pair* and download the file.
   * **Network settings:**
     * Select *Create security group*.
     * Check **Allow SSH traffic from** -> Select **My IP** (never choose *Anywhere* for SSH).
     * Check **Allow HTTPS traffic from the internet** and **Allow HTTP traffic from the internet**.
   * **Configure storage:** Keep default 8 GiB gp3 root volume.
4. Expand **Advanced details** at the bottom.
5. Under **Metadata version**, select **V2 only (recommended)** to secure your instance metadata.
6. Scroll down to **User data** and paste the following bash script to automatically bootstrap Node.js:
   ```bash
   #!/bin/bash
   # Update package references
   sudo apt-get update -y
   # Install Node.js LTS
   curl -fsSL https://deb.nodesource.com/setup_20.x | sudo -E bash -
   sudo apt-get install -y nodejs
   # Install PM2 globally to keep node process running
   sudo npm install pm2 -g
   ```
7. Click **Launch instance**.

## 7. Step-by-Step Guide: Managing EC2 via AWS CLI

### A. Launch an Instance
```bash
aws ec2 run-instances \
    --image-id ami-0c7217cdde317cfec \
    --count 1 \
    --instance-type t2.micro \
    --key-name my-ssh-key \
    --security-group-ids sg-0123456789abcdef0 \
    --metadata-options "HttpTokens=required,HttpEndpoint=enabled"
```
*`--metadata-options "HttpTokens=required"` enforces secure IMDSv2.*

### B. List IP Address of Running Instances
```bash
aws ec2 describe-instances \
    --filters "Name=instance-state-name,Values=running" \
    --query "Reservations[*].Instances[*].[InstanceId,PublicIpAddress]" \
    --output table
```

### C. Stopping and Terminating Instances
*   **Stop (Pause charges for CPU):**
    ```bash
    aws ec2 stop-instances --instance-ids i-0abcdef1234567890
    ```
*   **Terminate (Delete server entirely):**
    ```bash
    aws ec2 terminate-instances --instance-ids i-0abcdef1234567890
    ```

## 8. Connecting to Your Instance via SSH

### On Linux/macOS
1. Open your terminal and navigate to the directory where you saved `my-ssh-key.pem`.
2. Restrict file permissions:
   ```bash
   chmod 400 my-ssh-key.pem
   ```
3. Connect using the public IP:
   ```bash
   ssh -i "my-ssh-key.pem" ubuntu@54.210.44.12
   ```

### On Windows
*   **Method A (PowerShell/CMD):** Recent Windows builds include standard OpenSSH. Follow the same steps as Linux:
    1. Right-click the `.pem` file -> Properties -> Security -> Advanced. Disable inheritance and remove all permissions except your user account (read access).
    2. Run: `ssh -i "my-ssh-key.pem" ubuntu@54.210.44.12`
*   **Method B (PuTTY):**
    1. Convert `.pem` to `.ppk` using **PuTTYgen** (Load `.pem`, save private key).
    2. Open **PuTTY**, enter the host name `ubuntu@54.210.44.12`.
    3. In the left panel, navigate to Connection -> SSH -> Auth -> Credentials. Select your `.ppk` file under *Private key file for authentication*.
    4. Click **Open**.

## 9. Troubleshooting SSH Connection Failures

### A. Error: `Permission denied (publickey)`
*   **Causes:**
    *   You are logged in with the wrong username. Standard user names are:
        *   Ubuntu: `ubuntu`
        *   Amazon Linux / CentOS: `ec2-user`
        *   Debian: `admin`
        *   Windows: `Administrator`
    *   You specified the wrong `.pem` key file.
*   **Fix:** Double check the username and key filename.

### B. Error: `Connection timed out`
*   **Causes:**
    *   The instance Security Group does not allow inbound SSH traffic on Port 22 from your current IP.
    *   The instance was launched in a private subnet and does not have a public route or internet gateway.
*   **Fixes:**
    *   Go to the EC2 security group and update Port 22 inbound rules to include your new IP address.
    *   Ensure the instance has a public IP and sits in a public subnet with a route to an Internet Gateway.

## 10. EC2 Production Checklist

- [x] Choose the correct **AMI** based on your team's familiarity (Ubuntu vs. Amazon Linux).
- [x] Select an **Instance Type** that matches your workload; start with burstable general purpose (`t3.medium`) and upgrade as needed.
- [x] Ensure your root **EBS Volume** has "Delete on Termination" enabled so you don't pay for leftover disks when deleting servers.
- [x] Restrict **Security Group Inbound Port 22 (SSH)** to your specific IP address instead of opening it to the entire internet (`0.0.0.0/0`).
- [x] Set up an **Elastic IP** if you require a permanent static IP address for DNS records.
- [x] Schedule automatic backups using AWS Backup or EBS Snapshots.
- [x] Attach an **IAM Instance Profile** (Role) to the EC2 instance to let it access services like S3 or DynamoDB securely without storing access keys in your code.
- [x] Configure IMDSv2 as mandatory on all instances.
