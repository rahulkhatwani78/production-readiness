# AWS S3: Basics and Get/Put Objects (Beginner's Guide)

When running a production backend, storing user uploads (like profile pictures, PDF invoices, or videos) directly on your application server's local hard drive is a bad practice. If your server crashes or scales up to multiple instances, those files will be lost or out of sync.

**AWS S3 (Simple Storage Service)** is an object storage service designed to store and protect any amount of data (images, backups, website assets) with high availability and security.

---

## 1. What is AWS S3? (Layman's Terms)

### The Digital Storage Locker Analogy

Imagine you own a physical store. If you store all your extra stock, heavy cargo, and records in your tiny retail room, you will quickly run out of space, and a break-in or fire could destroy everything. 

Instead, you rent a locker at a massive, secure, and infinite **Self-Storage Warehouse (S3)** down the road. 

```
+-----------------------------------------------------------------+
|                         AWS S3 WAREHOUSE                        |
|                                                                 |
|  [ Bucket: user-avatars ]         [ Bucket: invoice-pdf ]       |
|  (Globally Unique Name)           (Globally Unique Name)        |
|          |                                |                     |
|    +-----+-----+                    +-----+-----+               |
|    |  Object   |                    |  Object   |               |
|    |  (File)   |                    |  (File)   |               |
|    +-----------+                    +-----------+               |
+-----------------------------------------------------------------+
```

Inside this warehouse, you organize your items using:
*   **Buckets (The Lockers):** These are the top-level containers. A bucket name is **globally unique**—no two AWS accounts in the world can have a bucket with the exact same name.
*   **Objects (The Items):** An object is the actual file (an image, a text document, a ZIP file) plus any extra information about it (metadata, like file size or content-type).
*   **Keys (The Label/Path):** The "key" is the full name or pathway to locate the object inside a bucket. For example, in the key `images/avatars/user-123.jpg`, S3 stores files flatly but uses slashes `/` to make it look like folders for organization.

## 2. Core Concepts of S3

### A. High Durability & Availability
S3 is designed for **99.999999999% durability** (known as "11 nines"). S3 achieves this by automatically copying your files across multiple physical datacenters inside your selected AWS Region.

### B. S3 Security: IAM Policies vs. Bucket Policies vs. ACLs
By default, **every bucket and file in S3 is completely private**. Access can be configured via:
*   **IAM Policies:** Attached to users or roles in your account. Best for granting access to internal developers or application servers (e.g., EC2/Lambda).
*   **Bucket Policies:** JSON policies attached directly to the bucket. Best for cross-account access or granting public access (e.g., letting anyone view image assets).
*   **Access Control Lists (ACLs):** Legacy system used to grant permissions on an individual object basis. *Recommendation: Disable ACLs and use bucket policies instead.*

## 3. Storage Classes Comparison Table

AWS offers several storage classes depending on how often data is accessed. Selecting the correct class optimizes costs.

| Storage Class | Use Case | Durability | Min Storage Duration | Retrieval Time | Cost (Storage / Retrieval) |
| :--- | :--- | :--- | :--- | :--- | :--- |
| **S3 Standard** | Active, frequently accessed files (profile images). | 99.999999999% | None | Instant | High / Free |
| **S3 Intelligent-Tiering** | Unknown or changing access patterns. | 99.999999999% | None | Instant | Automatic optimization fee |
| **S3 Standard-IA** | Infrequently accessed but needed immediately (invoices). | 99.999999999% | 30 days | Instant | Medium / Low fee per GB |
| **S3 One Zone-IA** | Non-critical, infrequent data (re-creatable thumbnails). | 99.999999999% (single AZ) | 30 days | Instant | Low / Low fee per GB |
| **S3 Glacier Instant** | Long-term archives accessed quarterly. | 99.999999999% | 90 days | Milliseconds | Very Low / Medium fee |
| **S3 Glacier Flexible** | Backups retrieved within hours. | 99.999999999% | 90 days | 1 min to 5 hours | Extremely Low / Medium fee |
| **S3 Deep Archive** | Compliance archives accessed once a year. | 99.999999999% | 180 days | 12 hours | Lowest / High fee |

## 4. Advanced Features

*   **S3 Versioning:** Keeps multiple versions of an object in the same bucket. Protecting against accidental overwrites or deletions.
*   **S3 Object Lock:** Block objects from being deleted or overwritten for a specific duration (WORM - Write Once Read Many), useful for regulatory compliance.
*   **S3 Transfer Acceleration:** Uses AWS CloudFront global edge locations to route file uploads over the fast AWS private network.
*   **S3 Multipart Upload:** Splits large files (larger than 100MB) into smaller chunks, uploading them in parallel. If a chunk upload fails, only that chunk needs to be resent.

## 5. Step-by-Step Guide: Managing S3 in the AWS Console

### Step 1: Create a Bucket
1. Log in to the **AWS Console**.
2. Search and select **S3**.
3. Click the orange **Create bucket** button.
4. Set configuration parameters:
   * **Bucket name:** Enter a globally unique, lowercase name (e.g., `company-invoices-2026-prod`).
   * **AWS Region:** Choose the region closest to your users.
   * **Object Ownership:** Keep **ACLs disabled** (default and recommended).
   * **Block Public Access settings:** Keep **Block all public access** checked to secure your files.
   * **Bucket Versioning:** Select **Enable** (to protect against accidental deletes).
   * **Default Encryption:** Keep set to **SSE-S3** (Amazon managed encryption).
5. Click **Create bucket**.

### Step 2: Write a Public Bucket Policy (e.g., for website assets)
To expose assets publicly, you must unblock public access and apply a bucket policy:
1. In S3, click your bucket, and select the **Permissions** tab.
2. Under *Block public access (bucket settings)*, click **Edit**, uncheck **Block all public access**, and click **Save changes**.
3. Scroll down to **Bucket policy** and click **Edit**. Paste the following JSON policy:
   ```json
   {
     "Version": "2012-10-17",
     "Statement": [
       {
         "Sid": "PublicReadGetObject",
         "Effect": "Allow",
         "Principal": "*",
         "Action": "s3:GetObject",
         "Resource": "arn:aws:s3:::YOUR-BUCKET-NAME/*"
       }
     ]
   }
   ```
4. Replace `YOUR-BUCKET-NAME` with your actual bucket name.
5. Click **Save changes**.

## 6. Step-by-Step Guide: Managing S3 via AWS CLI

### A. Managing Buckets
*   **Create a Bucket:**
    ```bash
    aws s3 mb s3://my-test-bucket-rahul-101
    ```
*   **List Buckets:**
    ```bash
    aws s3 ls
    ```

### B. Uploading and Downloading Objects
*   **Upload a File (PUT):**
    ```bash
    aws s3 cp document.pdf s3://my-test-bucket-rahul-101/invoices/document.pdf
    ```
*   **Download a File (GET):**
    ```bash
    aws s3 cp s3://my-test-bucket-rahul-101/invoices/document.pdf ./downloaded-document.pdf
    ```
*   **Sync Directories (Backup):**
    ```bash
    aws s3 sync ./local-backup s3://my-test-bucket-rahul-101/backups/ --delete
    ```
    *`--delete` removes files in S3 that are no longer present in the local directory.*

## 7. Node.js Integration (AWS SDK v3)

Here is a production-ready implementation utilizing modern SDK modules.

```javascript
const { S3Client, PutObjectCommand, GetObjectCommand } = require("@aws-sdk/client-s3");
const { getSignedUrl } = require("@aws-sdk/s3-request-presigner");
const fs = require("fs");

const s3Client = new S3Client({ region: "us-east-1" });
const BUCKET_NAME = "my-test-bucket-rahul-101";

/**
 * UPLOAD A FILE
 */
async function uploadFile(filePath, s3Key, mimeType) {
    try {
        const fileStream = fs.createReadStream(filePath);

        const uploadCommand = new PutObjectCommand({
            Bucket: BUCKET_NAME,
            Key: s3Key,
            Body: fileStream,
            ContentType: mimeType, // Correct MIME type ensures browsers render it
        });

        await s3Client.send(uploadCommand);
        console.log(`Successfully uploaded: ${s3Key}`);
        return s3Key;
    } catch (err) {
        console.error("S3 Upload Failed:", err);
        throw err;
    }
}

/**
 * GENERATE A SECURE TEMPORARY DOWNLOAD LINK
 */
async function generatePresignedUrl(s3Key, expirationSeconds = 900) {
    try {
        const downloadCommand = new GetObjectCommand({
            Bucket: BUCKET_NAME,
            Key: s3Key,
        });

        const url = await getSignedUrl(s3Client, downloadCommand, { expiresIn: expirationSeconds });
        return url;
    } catch (err) {
        console.error("Presigned URL Generation Failed:", err);
        throw err;
    }
}
```

## 8. Troubleshooting & Gotchas

### A. Frontend CORS Errors
*   **Symptom:** Browser blocks file requests or file uploads directly from React/Vue.
*   **Fix:** Configure CORS rules on your bucket.
    1. Go to the **Permissions** tab of the bucket in the AWS Console.
    2. Scroll to **Cross-origin resource sharing (CORS)** and paste:
       ```json
       [
         {
           "AllowedHeaders": ["*"],
           "AllowedMethods": ["GET", "PUT", "POST", "HEAD"],
           "AllowedOrigins": ["https://mywebsite.com"],
           "ExposeHeaders": ["ETag"]
         }
       ]
       ```

### B. Access Denied on Public Links
*   **Symptom:** Opening an S3 link results in XML showing `AccessDenied`.
*   **Fixes:**
    *   Ensure the bucket's *Block Public Access* is unchecked.
    *   Verify the *Bucket Policy* explicitly allows public `s3:GetObject`.
    *   Verify the file is not encrypted with a custom KMS key that public users can't decrypt.

### C. Recovering Deleted Files
*   **Symptom:** A file was accidentally deleted.
*   **Fix:** If S3 Versioning is enabled, deleting a file does not erase it; it places a **Delete Marker** on top of the version history.
    1. Go to the bucket in the console.
    2. Toggle the **Show versions** switch.
    3. Locate your file, find the "Delete Marker" version, and delete the Delete Marker. The original file will immediately reappear.

## 9. S3 Production Summary Checklist

- [x] Ensure the S3 Bucket Name is globally unique and lowercase.
- [x] Enforce "Block all public access" on the bucket by default.
- [x] Use **IAM Roles** on your server to authenticate with S3, avoiding hardcoded access keys.
- [x] Set appropriate `ContentType` headers (e.g., `image/png`, `application/pdf`) during upload so browsers display the files instead of forcing downloads.
- [x] Use **Pre-signed URLs** to securely share private files with temporary expiration limits (e.g., 10-15 minutes).
- [x] Enable **S3 Versioning** on the bucket to prevent accidental file overwrites or deletions.
- [x] Configure **S3 Lifecycle Rules** to automatically move old files to cheaper classes (like S3 Glacier) or delete temporary logs after 30 days.
- [x] Set up **CORS (Cross-Origin Resource Sharing)** on the bucket if your frontend application needs to upload files directly to S3.
