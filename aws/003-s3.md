# AWS S3: Basics and Get/Put Objects (Beginner's Guide)

When running a production backend, storing user uploads (like profile pictures, PDF invoices, or videos) directly on your application server's local hard drive is a bad practice. If your server crashes or scales up to multiple instances, those files will be lost or out of sync.

**AWS S3 (Simple Storage Service)** is an object storage service designed to store and protect any amount of data (images, backups, website assets) with high availability and security.

---

## 1. What is AWS S3? (Layman's Terms)

### The Digital Storage Locker Analogy

Imagine you own a physical store. If you store all your extra stock, heavy cargo, and records in your tiny retail room, you will quickly run out of space, and a break-in or fire could destroy everything. 

Instead, you rent a locker at a massive, secure, and infinite **Self-Storage Warehouse (S3)** down the road. 

```
+-----------------------------------------------------------------+
|                         AWS S3 WAREHOUSE                        |
|                                                                 |
|  [ Bucket: user-avatars ]         [ Bucket: invoice-pdf ]       |
|  (Globally Unique Name)           (Globally Unique Name)        |
|          |                                |                     |
|    +-----+-----+                    +-----+-----+               |
|    |  Object   |                    |  Object   |               |
|    |  (File)   |                    |  (File)   |               |
|    +-----------+                    +-----------+               |
+-----------------------------------------------------------------+
```

Inside this warehouse, you organize your items using:

*   **Buckets (The Lockers):** These are the top-level containers. Think of them like separate file cabinets. A bucket name is **globally unique**—no two AWS accounts in the world can have a bucket with the exact same name (e.g., if you create a bucket named `my-photos`, no one else in the world can use that name).
*   **Objects (The Items):** An object is the actual file (an image, a text document, a ZIP file) plus any extra information about it (metadata, like file size or content-type).
*   **Keys (The Label/Path):** The "key" is the full name or pathway to locate the object inside a bucket. For example, in the key `images/avatars/user-123.jpg`, the folders don't physically exist; S3 stores files flatly but uses slashes `/` to make it look like folders for organization.

## 2. Core Concepts of S3

To use S3 effectively, you need to understand these four core concepts:

### A. High Durability & Availability
S3 is designed for **99.999999999% durability** (known as "11 nines"). This means if you store 10,000,000 files in S3, you might lose one file every 10,000 years. S3 achieves this by automatically copying your files across multiple physical datacenters within a region.

### B. Storage Classes (Cost Optimization)
Not all files are accessed at the same rate. S3 offers different storage classes to save money:
1.  **S3 Standard:** For active, frequently accessed files (e.g., website graphics, user profile photos).
2.  **S3 Standard-IA (Infrequent Access):** For files you don't access often but need instantly when requested (e.g., monthly bank statements). Storage is cheaper, but you pay a small fee to retrieve the data.
3.  **S3 Glacier (Archive):** For long-term backups (e.g., system logs from 3 years ago). Storage is extremely cheap, but retrieving files can take anywhere from a few minutes to hours.

### C. Default Privacy & Security
By default, **every bucket and file in S3 is completely private**. If a user tries to access an S3 link (e.g., `https://my-bucket.s3.amazonaws.com/secret-file.pdf`) without signing in, they will receive an `Access Denied` error. Access can be granted through:
*   **IAM Roles/Policies:** Granting permission to your internal servers or developers.
*   **Bucket Policies:** JSON configurations that allow public access (e.g., letting anyone view images on your public blog).
*   **Pre-signed URLs:** Generating a temporary secure link (like a ticket that expires in 10 minutes) to allow a user to upload or download a private file.

## 3. GET vs. PUT Objects

In S3, operations are simple API calls:

*   **PUT Object (Upload):** Sending a file from your computer or server to an S3 bucket.
*   **GET Object (Download / Read):** Retrieving a file from an S3 bucket to read its contents or save it locally.

## 4. Hands-On Command Reference (AWS CLI)

Make sure your terminal is configured with your AWS credentials.

### Managing Buckets
*   **Create a new bucket:**
    ```bash
    aws s3 mb s3://my-super-unique-bucket-12345
    ```
    *(Note: `mb` stands for "make bucket".)*

*   **List all your buckets:**
    ```bash
    aws s3 ls
    ```

*   **Delete a bucket (must be empty first):**
    ```bash
    aws s3 rb s3://my-super-unique-bucket-12345
    ```
    *(Note: `rb` stands for "remove bucket".)*

### Managing Objects (GET & PUT)
*   **Upload a file (PUT Object):**
    ```bash
    aws s3 cp photo.jpg s3://my-super-unique-bucket-12345/images/photo.jpg
    ```
    *(Note: `cp` stands for "copy".)*

*   **Download a file (GET Object):**
    ```bash
    aws s3 cp s3://my-super-unique-bucket-12345/images/photo.jpg ./downloaded-photo.jpg
    ```

*   **List files in a bucket:**
    ```bash
    aws s3 ls s3://my-super-unique-bucket-12345/images/
    ```

*   **Delete a file:**
    ```bash
    aws s3 rm s3://my-super-unique-bucket-12345/images/photo.jpg
    ```

*   **Sync local folder to S3 (Backup):**
    ```bash
    aws s3 sync ./my-local-folder s3://my-super-unique-bucket-12345/backups/
    ```
    *(This is highly efficient; it only uploads new or modified files).*

## 5. Node.js Implementation Example (AWS SDK v3)

Let's look at how to upload and download files programmatically in a Node.js backend.

### Step 1: Install the SDK
AWS SDK v3 is modular, so we only install the S3 client instead of the whole AWS suite:

```bash
npm install @aws-sdk/client-s3 @aws-sdk/s3-request-presigner
```

### Step 2: Code Implementation (`s3Service.js`)

Create a script to connect to S3 and handle uploads (PUT) and downloads (GET):

```javascript
const { S3Client, PutObjectCommand, GetObjectCommand } = require("@aws-sdk/client-s3");
const { getSignedUrl } = require("@aws-sdk/s3-request-presigner");
const fs = require("fs");

// 1. Initialize S3 Client
// In production on EC2/Lambda, AWS automatically detects credentials.
// For local testing, ensure your env variables are set (AWS_ACCESS_KEY_ID, etc.)
const s3Client = new S3Client({ region: "us-east-1" });
const BUCKET_NAME = "my-super-unique-bucket-12345";

/**
 * UPLOAD A FILE (PUT Object)
 */
async function uploadToS3(filePath, s3Key) {
    try {
        const fileStream = fs.createReadStream(filePath);

        const uploadCommand = new PutObjectCommand({
            Bucket: BUCKET_NAME,
            Key: s3Key,
            Body: fileStream,
            ContentType: "image/jpeg", // Helps browser render the file instead of downloading it
        });

        const result = await s3Client.send(uploadCommand);
        console.log(`Success: File uploaded. Metadata:`, result);
        return s3Key;
    } catch (err) {
        console.error("Error uploading file to S3:", err);
        throw err;
    }
}

/**
 * GENERATE A TEMPORARY DOWNLOAD LINK (Pre-signed GET URL)
 * This is the secure production way to let users view private files without making the bucket public.
 */
async function getTempDownloadLink(s3Key) {
    try {
        const downloadCommand = new GetObjectCommand({
            Bucket: BUCKET_NAME,
            Key: s3Key,
        });

        // Link will work for 15 minutes (900 seconds)
        const url = await getSignedUrl(s3Client, downloadCommand, { expiresIn: 900 });
        console.log(`Generated Pre-signed URL: ${url}`);
        return url;
    } catch (err) {
        console.error("Error generating signed URL:", err);
        throw err;
    }
}

// Example usage execution:
(async () => {
    // 1. Upload file
    await uploadToS3("./my-profile.jpg", "avatars/user-99.jpg");

    // 2. Get secure temporary link for user
    await getTempDownloadLink("avatars/user-99.jpg");
})();
```

## 6. S3 Production Summary Checklist

- [ ] Ensure the S3 Bucket Name is globally unique and lowercase.
- [ ] Enforce "Block all public access" on the bucket by default.
- [ ] Use **IAM Roles** on your server to authenticate with S3, avoiding hardcoded access keys.
- [ ] Set appropriate `ContentType` headers (e.g., `image/png`, `application/pdf`) during upload so browsers display the files instead of forcing downloads.
- [ ] Use **Pre-signed URLs** to securely share private files with temporary expiration limits (e.g., 10-15 minutes).
- [ ] Enable **S3 Versioning** on the bucket to prevent accidental file overwrites or deletions.
- [ ] Configure **S3 Lifecycle Rules** to automatically move old files to cheaper classes (like S3 Glacier) or delete temporary logs after 30 days.
- [ ] Set up **CORS (Cross-Origin Resource Sharing)** on the bucket if your frontend application needs to upload files directly to S3.
