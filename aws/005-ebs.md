# AWS EBS (Elastic Block Store): A Beginner's Guide

When running an application on a virtual server like AWS EC2, the server needs a local hard drive to store the operating system, run code, write log files, and store database files. 

**AWS EBS (Elastic Block Store)** provides high-performance block storage volumes (virtual hard drives) designed specifically to be attached to EC2 instances.

## 1. What is AWS EBS? (Layman's Terms)

### The USB Flash Drive Analogy

Imagine you buy a desktop computer tower (this is like an **EC2 Instance**). 

An **EBS Volume** is like a **USB External SSD** or flash drive. 

```
+------------------------+             +------------------------+
|       EC2 INSTANCE     |             |       EBS VOLUME       |
|    (Virtual Computer)  |             |  (External Hard Drive) |
|                        |   cable     |                        |
|  [ Operating System ]  |<===========>|  [ Database Files ]    |
|                        | (Attach/Det)|  [ Application Logs ]  |
+------------------------+             +------------------------+
```

*   **Detachable Persistence:** You plug the USB drive into your computer tower to save files. If the computer tower's processor burns out, you don't lose your files. You simply unplug the USB drive, get a brand-new computer tower, plug the USB drive in, and all your files are immediately available.
*   **Network-Attached:** Unlike physical hard drives inside your laptop, EBS volumes are connected to EC2 instances over a super-fast private network connection behind the scenes.
*   **Availability Zone Bound:** An EBS volume lives in a specific Availability Zone (AZ) (e.g., `us-east-1a`). It can only be plugged into an EC2 instance that is running in that **exact same Availability Zone**.

## 2. Creating an EBS Volume

Before you can use a virtual hard drive, you must create it in your AWS account and specify its size and type.

### Popular EBS Volume Types
1.  **gp3 (General Purpose SSD - Recommended):** The standard, default choice. Offers a great balance of price and performance for web servers, development environments, and small databases.
2.  **io2 (Provisioned IOPS SSD):** Designed for extreme, high-performance database workloads that require guaranteed read/write speeds.
3.  **sc1 (Cold HDD):** Cheap storage for large data sets that are rarely accessed (like logs or archive backups).

### Creating a Volume via AWS CLI

Open your terminal and run the following command to create a raw, unformatted `80 GB` SSD volume:

```bash
aws ec2 create-volume \
  --size 80 \
  --availability-zone us-east-1a \
  --volume-type gp3
```
*   `--size`: Size of the hard drive in Gigabytes.
*   `--availability-zone`: The zone where the drive will live (must match your EC2 instance location).
*   `--volume-type`: The storage class (we chose general-purpose `gp3`).

*(This command returns a JSON block containing your `VolumeId`, which looks like `vol-0123456789abcdef0`).*

## 3. Attaching and Mounting EBS Volumes

Once a volume is created, you must perform two steps to use it: **Attach** it (plug it in) and **Mount** it (format it with a filesystem so the OS can read/write files).

### Step 1: Attach the Volume to your EC2 Instance
Run the following command to connect your new volume to your virtual computer:

```bash
aws ec2 attach-volume \
  --volume-id vol-0123456789abcdef0 \
  --instance-id i-0987654321fedcba0 \
  --device /dev/sdf
```
*   `--volume-id`: The ID of the EBS volume you created.
*   `--instance-id`: The ID of your running EC2 instance.
*   `--device`: The target device name (path) exposed to the instance.

---

### Step 2: Format and Mount the Volume (Linux OS commands)
Now, log in to your Linux EC2 instance via SSH to tell the Operating System to recognize the new disk.

1.  **List available storage devices:**
    ```bash
    lsblk
    ```
    *(You will see your new disk listed, often renamed by the OS to `/dev/xvdf` or `/dev/nvme1n1`).*

2.  **Check if the disk has data:**
    > [!WARNING]
    > **Never format a disk that already has data**, as this will wipe it out. Check if it is empty:
    ```bash
    sudo file -s /dev/xvdf
    ```
    *If it returns `/dev/xvdf: data`, it is a clean, unformatted disk.*

3.  **Format the disk with a filesystem:**
    Format the raw disk using the standard Linux `ext4` filesystem:
    ```bash
    sudo mkfs -t ext4 /dev/xvdf
    ```

4.  **Create a mount folder:**
    Create a folder directory where you want this drive to be accessed:
    ```bash
    sudo mkdir /mnt/my-data
    ```

5.  **Mount the drive:**
    Link the formatted device to your folder:
    ```bash
    sudo mount /dev/xvdf /mnt/my-data
    ```
    *Now, any file you save inside `/mnt/my-data` will be physically stored on your EBS volume.*

6.  **Configure auto-mount on system restarts:**
    By default, if you restart the EC2 instance, the volume will unmount. To make it permanent, add it to the `/etc/fstab` configuration file. Run `blkid /dev/xvdf` to find the disk's UUID, and append a line in `/etc/fstab` like:
    ```text
    UUID=your-disk-uuid-here  /mnt/my-data  ext4  defaults,nofail  0  2
    ```

## 4. EBS Snapshots: Creating Backups

### The Polaroid Photo Analogy

Imagine you are painting a picture. Before starting a risky new detail, you take a **Polaroid Photo (Snapshot)** of the canvas. The photo is tiny and doesn't take up the space of a real canvas. If you mess up the painting, you can buy a brand-new blank canvas and paint it exactly like the photo to restore your work.

*   An **EBS Snapshot** is a point-in-time copy of your volume.
*   Snapshots are stored behind the scenes in AWS S3 (highly secure and durable).
*   **Incremental Backups:** S3 only stores the data blocks that have changed since your last snapshot, saving significant storage costs.

### Creating a Snapshot via AWS CLI

```bash
aws ec2 create-snapshot \
  --volume-id vol-0123456789abcdef0 \
  --description "Weekly backup of production database"
```
*(This returns a JSON block with a `SnapshotId`, which looks like `snap-0123456789abcdef0`).*

---

## 5. Creating a Volume using a Snapshot (Restore / Move)

You can restore a snapshot to recreate a identical volume. This is useful for:
*   Restoring lost data from a backup.
*   **Moving data to a different Availability Zone:** Since EBS volumes are tied to one AZ, you can snapshot a volume in `us-east-1a`, and restore that snapshot into a new volume in `us-east-1b`.
*   Resizing a volume (restoring a 10GB snapshot into a 50GB volume).

### Creating a restored volume via AWS CLI

```bash
aws ec2 create-volume \
  --snapshot-id snap-0123456789abcdef0 \
  --availability-zone us-east-1b \
  --volume-type gp3
```
*   `--snapshot-id`: The backup ID you want to restore.
*   `--availability-zone`: You can specify a different AZ to replicate your disk elsewhere!

Once created, you can attach this new volume to an EC2 instance in `us-east-1b` and mount it to read your backed-up files.

---

## 6. EBS Production Summary Checklist

- [ ] Create EBS volumes in the **exact same Availability Zone** as the target EC2 instance.
- [ ] Use `gp3` volumes for general workloads to optimize cost and performance.
- [ ] Always check for existing files (`sudo file -s /dev/xxx`) before formatting a disk to prevent data loss.
- [ ] Configure auto-mounting in `/etc/fstab` using UUIDs so disks remain attached after server reboots.
- [ ] Set up automated backup schedules using **AWS Lifecycle Manager (DLM)** to capture snapshots daily/weekly.
- [ ] Unmount volumes (`sudo umount /mnt/my-data`) before detaching them to prevent filesystem corruption.
- [ ] To transfer an EBS volume's data to a different region or AZ, take a Snapshot, copy it, and restore it in the target location.
- [ ] Enable EBS Encryption by default to secure data at rest.
